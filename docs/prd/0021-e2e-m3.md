# PRD 0021 — E2E do M3: dois navegadores disputam o mesmo assento (E5, T4b)

- **Task:** docs/tasks/0021-e2e-m3.md
- **Branch:** feature/0021-e2e-m3
- **Data:** 2026-09-29
- **Status:** ativo

## Objetivo

Fechar o E5 e o marco **M3**. A disputa pelo mesmo assento passa a ser provada com navegadores reais (Playwright, dois contextos isolados), contra a stack real (API + PG + Redis + RabbitMQ pelo compose) e o proxy `/api` do ADR 0009. O teste roda num job de CI próprio (decisão do usuário no refinamento E5).

Entram também duas correções:
- o teste instável do relay do outbox, visto no CI do PR #47;
- o não-bloqueante da auditoria 0020 (`aoVencer` estável).

## Escopo

- `@playwright/test` (Chromium) com Page Object Model (ADR 0006);
- seed SQL da sessão de teste;
- 2 jornadas: M3 e o caminho feliz cartaz → filme → sessão;
- workflow `e2e.yml`;
- correção do teste do relay;
- `useCallback` do `aoVencer` + teste de contagem exata;
- documentação.

## Fora de escopo

- E2E contra a URL pública (E0c-CD);
- screenshot/regressão visual;
- checkout (E6/E8);
- outros navegadores (Firefox/WebKit): Chromium basta para a jornada crítica.

## Requisitos funcionais

- RF01 — **Playwright** (`web/playwright.config.ts`):
  - `testDir: 'e2e'`, projeto Chromium, `baseURL http://localhost:4173`;
  - `webServer` = `npm run build && vite preview` (o preview repete o proxy `/api` → `:8080`), com `reuseExistingServer: true`;
  - `trace: 'retain-on-failure'`, reporter `list` + `html`, `retries: 0`, `forbidOnly: true`;
  - timeout de `expect` de 15 s (polling 4 s + cache de 3 s do servidor).
- RF02 — **Page Object** (`web/e2e/PaginaSessao.ts`):
  - `abrir(id)`, `assento(fileira, n)` por role/nome acessível, `alternar`, `reservar`, `liberar(codigo)`, `aviso`;
  - seletores por role e nome, nunca por classe CSS.
- RF03 — **Seed** (`web/e2e/seed.sql`):
  - cria a sala "Sala E2E &lt;timestamp&gt;" (4 × 8) e uma sessão agendada daqui a 2 dias para o filme 1;
  - cada execução gera uma sessão nova, sem colisão entre execuções locais repetidas;
  - o teste descobre a sessão por `GET /api/filmes/1/sessoes` (a mais recente cujo nome começa por "Sala E2E").
- RF04 — **Jornada M3** (`web/e2e/m3.spec.ts`), com dois `browser.newContext()`, A e B (cookies de carrinho distintos):
  1. A e B abrem a mesma sessão;
  2. B seleciona C4 (ainda livre);
  3. A seleciona C4 e reserva → C4 aparece como "reservado para você" em A;
  4. B reserva → aviso "O assento C4 acabou de ser reservado por outra pessoa." e C4 "ocupado" em B;
  5. A libera C4 → B vê C4 livre pelo polling, sem recarregar a página;
  6. B reserva C4 com sucesso;
  7. limpeza: B libera.
- RF05 — **Jornada feliz**: cartaz → link do filme 1 → chip de sessão "Sala E2E" → a página da sessão abre o mapa (grid acessível).
- RF06 — **Workflow `.github/workflows/e2e.yml`**:
  - dispara em PR/push quando mudam `web/**`, `internal/reserva/**`, `internal/sessao/**`, `internal/catalogo/**`, `cmd/**`, `migrations/**` ou o próprio workflow;
  - `ubuntu-24.04-arm`, actions pinadas por SHA, `permissions: contents: read`, timeout de 20 min.
  - Passos:
    1. `.env.docker-compose` gerado a partir do `.example`, com `JWT_SEGREDO` aleatório por execução e `TMDB_API_TOKEN` vazio;
    2. `docker compose --profile app up --build -d`;
    3. espera por `/health`;
    4. seed via `docker compose exec -T postgres psql`;
    5. `npm ci`;
    6. `npx playwright install --with-deps chromium`;
    7. `npx playwright test`.
  - Em falha: upload do relatório/trace e `docker compose logs`. Sempre: `down -v`.
- RF07 — **Relay** (`internal/outbox/relay_integration_test.go`, `TestRelay_BrokerIndisponivelNaoCrashaEReentrega`):
  - o broker é **parado antes** de enfileirar (hoje o relay podia publicar antes do `Stop` terminar);
  - `t.Cleanup` religa o broker se o teste falhar no meio, sem cascata nos testes seguintes;
  - a semântica é preservada: relay rodando com o broker fora, evento pendente, broker volta, evento publicado.
- RF08 — **`aoVencer` estável** (auditoria 0020): `useCallback` em `PaginaSessao`; o teste "hold vencido" confere **exatamente uma** reconsulta dos holds.

## Requisitos não funcionais

- RNF01 — Sem sleep: só `expect(...).toHaveAccessibleName(..., {timeout})` e esperas por estado.
- RNF02 — Contextos isolados: cada navegador tem seu próprio cookie `morfeu_carrinho`.
- RNF03 — O Vitest ignora `e2e/` (`test.exclude`).
- RNF04 — `test-results/` e `playwright-report/` ficam no `.gitignore`.

## Regras de negócio

- RN01 — Exatamente um dono vence a disputa (ADR 0008). O perdedor recebe a recusa com o assento nomeado e o mapa atualizado (ADR 0009 + PRD 0020).
